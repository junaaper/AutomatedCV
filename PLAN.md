# Plan: Agentic Job-Application Copilot (AutomatedCV)

## Context
Greenfield portfolio project (dir currently holds only an empty `dummy.html`). A user pastes a job posting; a LangGraph agent extracts requirements, retrieves CV evidence via pgvector RAG, scores fit, drafts a cover letter, **pauses for human approval/edit**, then saves to a tracker. Must run indefinitely on free tiers (Render + Neon + Cloudflare Pages + Groq/Gemini), survive backend sleep (Postgres checkpointer), and keep working when the LLM is down (demo mode). Built **phased, MVP first**, committed in small logical commits and pushed to a GitHub repo the user creates.

Decisions: Gemini embeddings (768-dim, swappable), CV input = PDF + pasted text, frontend on Cloudflare Pages, commits authored by user only (no Claude trailers/attribution).

## Key design
**Data model (Alembic):** `users` (email, argon2 hash, is_demo, created_at), `cv_documents`, `cv_chunks` (text, `vector(768)`, HNSW index), `applications` (company, title, posting text, requirements JSON, fit_score, fit_breakdown JSON, cover_letter, status enum: draft/applied/interview/offer/rejected, thread_id), `llm_usage` (user_id, date, calls, tokens), `refresh_tokens`. LangGraph's `PostgresSaver.setup()` owns its own checkpoint tables.

**LLM/embedding factory (`agent/llm.py`):** `LLM_PROVIDER=groq|gemini|openrouter|fake`, `LLM_MODEL=...`, via `langchain.chat_models.init_chat_model` (OpenRouter through OpenAI-compatible base_url). `EMBED_PROVIDER=gemini|fake` (fake = deterministic hash embeddings for tests). Switching providers is config only.

**Graph (`agent/graph.py`)**, `StateGraph` with Postgres checkpointer, `thread_id` per application run:
1. `extract_requirements`: structured output (Pydantic: title, company, must_have[], nice_to_have[], seniority)
2. `retrieve_evidence`: pgvector top-k CV chunks per requirement (a tool call)
3. `score_fit`: per-requirement match/partial/missing + evidence quote, plus a weighted 0–100 score
4. `draft_cover_letter`: grounded in the matched evidence only
5. `human_review`: `interrupt()` with the draft. Resumes via `Command(resume={action: approve|edit|revise|reject, ...})`. `revise` + feedback loops back to step 4; `edit` takes the user's text verbatim
6. `save_application`: writes the tracker row (the only DB write, which happens after approval)

The API streams node progress to the UI over SSE (`astream(stream_mode="updates")`). Endpoints: `POST /runs` (start), `GET /runs/{id}` (state, so a pause survives sleep and reload), `POST /runs/{id}/resume`.

**Auth:** argon2-cffi, PyJWT short-lived access token (memory) + rotating refresh token in an httpOnly `SameSite=None; Secure` cookie (Pages and Render are on different origins). Turnstile is verified server-side on signup/login, and CI uses Cloudflare's always-pass test keys. CORS is locked to the frontend origin.

**Limits:** slowapi per-user/IP request limits. A daily quota dependency checks and increments `llm_usage` before each LLM-backed run and returns 429 with the reset time. The limits are env-configurable.

**Demo mode:** "Try the demo" creates an ephemeral `is_demo` user cloned from a seed CV (so visitors don't collide), with 3 sample postings. Demo runs go through the **real graph and checkpointer**, but with `FakeListChatModel` loaded from recorded responses (`demo/fixtures/*.json`, generated by `scripts/record_demo.py` against a real LLM) and precomputed embeddings, so it works even if the LLM is down. Startup purges demo users older than 24h.

**Cold start:** on load the frontend polls `/healthz` and shows a "Waking up the server… (Ns)" screen with a short explanation, then continues.

**Deploy:** Dockerfile (python-slim + uv). Render's free plan has no pre-deploy hook, so the container entrypoint runs `alembic upgrade head` and then uvicorn. `render.yaml` blueprint. Neon `DATABASE_URL` with pgvector enabled. Cloudflare Pages with Git integration, `VITE_API_URL`, and `_redirects` for the SPA.

## Phases (each = several commits, push at end of each)
0. **Repo bootstrap:** `git init`, .gitignore, README stub, .env.example, then push once the user provides the remote URL.
1. **Backend skeleton:** FastAPI app, config, `/healthz`, DB, Alembic initial migration (pgvector), docker-compose for local Postgres (`pgvector/pgvector:pg16`), pytest + fixtures.
2. **Auth:** users, argon2, JWT/refresh, Turnstile, tests.
3. **CV + RAG:** PDF/text upload, chunking, embedding factory, retrieval, tests with fake embeddings.
4. **Agent graph:** nodes, schemas, checkpointer, interrupt/resume, SSE endpoints, tracker save, tests with fake chat models (including a resume-after-restart test using a fresh graph instance on the same DB).
5. **Frontend MVP:** auth pages with Turnstile, CV page, new-application flow (streamed steps, then a review panel with score, requirement/evidence table, editable letter, Approve/Revise/Reject), tracker with status updates, waking-up screen.
6. **Demo mode:** seed, ephemeral users, recorded fixtures, record script, "Try demo" button.
7. **Limits & quotas:** slowapi plus a daily quota, with a usage indicator in the UI.
8. **CI:** GitHub Actions with ruff, pytest (Postgres service container), frontend typecheck/build, Playwright e2e (backend with `LLM_PROVIDER=fake`), and a weekly cron. Pinned deps (uv.lock, package-lock).
9. **Evals:** 20 postings plus expected must-haves, a score band, and required keywords. In CI, structural evals run deterministically on recorded responses. `evals-live.yml` runs weekly against the real LLM (secret key) and checks thresholds (requirement recall ≥ 0.8, score within band, no hallucinated skills absent from the CV).
10. **Observability & deploy:** Sentry (backend + frontend), LangSmith env tracing, render.yaml, Pages config, and a README with architecture diagram, setup, and a link placeholder for the walkthrough video.
