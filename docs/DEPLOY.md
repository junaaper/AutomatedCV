# Deploying AutomatedCV (all free tiers)

```
Browser ──▶ Cloudflare Pages (React app)
               └─ /api/* ──▶ Pages Function proxy ──▶ Render (FastAPI, Docker) ──▶ Neon Postgres + pgvector
                                                                │
                                                                └──▶ Groq / Gemini / OpenRouter
```

The Pages Function makes the API same-origin, so the refresh-token cookie is first-party
(no third-party-cookie blocking, no CORS). Total cost: £0, no credit card.

Time needed: about 30 minutes.

---

## 1. Database: Neon

1. Create a project at <https://neon.tech> in **AWS US East 2 (Ohio)**, the same region as Render's Ohio.
2. Copy the **pooled** connection string. `postgresql://…` is fine; the app adds the driver.
3. Optional but recommended: use a separate project or branch from the one you develop
   against, and **reset the password** if it has ever been pasted anywhere.

Migrations run automatically when the container starts. pgvector is enabled by migration `0001`.

## 2. Captcha: Cloudflare Turnstile

1. Cloudflare dashboard → Turnstile → **Add widget**. Choose the hostname you'll use, e.g.
   `automatedcv.pages.dev`, and the **Invisible** or **Managed** mode.
2. Keep the **site key** (for Pages) and the **secret key** (for Render).

## 3. API: Render

1. <https://dashboard.render.com> → **New → Blueprint** → select this repo. `render.yaml`
   defines the service: Docker, free plan, Ohio, health check `/healthz`.
2. Fill in the `sync: false` variables:

   | Variable | Value |
   | --- | --- |
   | `DATABASE_URL` | Neon pooled connection string |
   | `FRONTEND_ORIGIN` | `https://<your-project>.pages.dev` |
   | `GROQ_API_KEY` | <https://console.groq.com/keys> |
   | `GOOGLE_API_KEY` | <https://aistudio.google.com/apikey> (embeddings) |
   | `TURNSTILE_SECRET_KEY` | from step 2 |
   | `SENTRY_DSN` | optional, step 6 |
   | `LANGSMITH_API_KEY` | optional, step 6 (also set `LANGSMITH_TRACING=true`) |

   `JWT_SECRET` is generated by Render. `COOKIE_PATH_PREFIX=/api` is preset for the proxy.
3. Deploy, then open `https://<service>.onrender.com/healthz`; it should return `{"status":"ok"}`.

> Free services sleep after 15 idle minutes and take ~30–50 s to wake. The frontend shows a
> "waking up the server" screen during this time.

## 4. Frontend: Cloudflare Pages

1. Cloudflare dashboard → Workers & Pages → **Create → Pages → Connect to Git** → this repo.
2. Build settings:
   - Root directory: `frontend`
   - Build command: `npm run build`
   - Output directory: `dist`
3. Environment variables (Production):

   | Variable | Value |
   | --- | --- |
   | `VITE_API_URL` | `/api` |
   | `VITE_TURNSTILE_SITE_KEY` | site key from step 2 |
   | `API_ORIGIN` | `https://<service>.onrender.com` (used by `functions/api/[[path]].js`) |
   | `VITE_SENTRY_DSN` | optional, step 6 |
   | `NODE_VERSION` | `24` |

4. Deploy. `public/_redirects` handles SPA routes and `public/_headers` sets security headers.

## 5. Smoke test

- Open the site. You may see the wake-up screen for up to a minute on the first visit.
- Click **Explore the demo, no signup**, then analyze a sample posting. This uses recorded
  responses, so it works even without LLM keys.
- Create a real account, upload a CV, and analyze a pasted posting (uses the live LLM).
- Reload during review: the draft should still be there.

## 6. Monitoring (optional)

- **Sentry**: create a FastAPI project and a React project; put their DSNs in
  `SENTRY_DSN` (Render) and `VITE_SENTRY_DSN` (Pages). The React SDK is only downloaded
  when a DSN is set.
- **LangSmith**: create an API key; on Render set `LANGSMITH_TRACING=true` and
  `LANGSMITH_API_KEY`. Each agent run is traced with its run id as metadata.

## 7. Weekly live evals (optional)

GitHub repo → Settings → Secrets and variables → Actions → add `GROQ_API_KEY` and
`GOOGLE_API_KEY`. The `Live evals` workflow then runs every Monday (or on demand from
the Actions tab) and posts its report to the run summary.

## Keeping it alive for years

| Risk | Mitigation already in place |
| --- | --- |
| LLM free tier shrinks or a model is retired | `LLM_PROVIDER` / `LLM_MODEL` env vars (Groq, Gemini, OpenRouter). Groq retired `llama-3.3-70b-versatile` during development; switching took one variable. |
| LLM API down or rate-limited | Demo mode replays recorded runs; daily quotas plus a global cap protect the key. |
| Database pauses | Neon scales to zero and wakes on the next query (unlike Supabase's manual unpause). |
| Something upstream breaks silently | CI runs weekly on a cron, and live evals run weekly. |
| Every free tier dies | Record the walkthrough video linked in the README. |

**When you change prompts or switch models**, re-record the replay data with live keys
configured locally:

```bash
cd backend
uv run python scripts/record_demo.py                 # demo fixtures
uv run python evals/run_evals.py --mode record --sleep 4   # eval cassettes
```
